# 上板与素材验收

## 演示场景

“小龙广场”商场信息屏：平时轮播促销海报、楼层导览、消防安全标语和店铺广告；客流高峰切到“注意”告示；紧急时切到疏散路线图（东西两侧出口），并配合字幕、边框闪烁和警报音。商场名、吉祥物“小龙”、店铺和平面图均为本项目原创绘制；路线和优惠是演示用的预置内容，不是真实商场的疏散预案。

## TF 卡放什么

将 `assets/sdcard/` 中六个文件直接复制到 FAT32 卡根目录（先删掉卡上旧的 PIC 文件）：

| 文件名 | 尺寸 | 内容 | 用途 |
|---|---|---|---|
| `PIC1.BMP` | $640\times480$ | 冬季焕新季促销海报 | 普通模式轮播 |
| `PIC2.BMP` | $800\times600$ | 1F 楼层导览与推荐路线 | 普通模式轮播，验证 FPGA 区域平均缩小 |
| `PIC3.BMP` | $640\times480$ | 消防安全标语 | 普通模式轮播 |
| `PIC4.BMP` | $480\times360$ | 书店咖啡广告 | 普通模式轮播，验证 FPGA 双线性放大 |
| `PIC5.BMP` | $640\times480$ | 温馨提示：客流较大 | 注意模式 |
| `PIC6.BMP` | $640\times480$ | 紧急疏散：东西两侧出口 | 紧急模式 |

均为 24 位非压缩 BMP，由 `scripts/prepare_assets.py` 生成，底部 32 行留给字幕条，合计约 4.9 MB。根目录文件名必须保持不变；支持 FAT32 的首个 MBR 分区或无分区 FAT32 卷，不支持 exFAT、GPT。声音由 FPGA 合成，卡上不需要 WAV；`assets/alarm_reference.wav` 只供电脑试听警报音色。

SDRAM 共 $2^{21}$ 个 32 位字，每张图 $640\times480=307200$ 字，最多 $\lfloor 2097152/307200\rfloor=6$ 张，因此本版正好用满六个图位。

## 支持的图片尺寸与缩放

加载时由 FPGA 统一适配到 $640\times480$ 后再存入 SDRAM，显示链路不变：

| 项目 | 规格 |
|---|---|
| 格式 | 24 位非压缩 BMP，自下而上或自上而下行序均可 |
| 宽、高范围 | 各自 16–2048 像素，任意组合（含竖图、超宽图） |
| 比例处理 | 保持原比例，缩放到能完整放进 $640\times480$ 的最大尺寸并居中，其余区域填纯黑 |
| 缩小（宽 ≥ 640 或高 ≥ 480） | 区域平均（每个输出像素取它覆盖的源像素平均值），缩小比例最大 3.2 倍 |
| 放大（宽 < 640 且高 < 480） | 双线性插值，最大 30 倍（16×16 → 480×480） |
| 典型示例 | 1920×1080 → 640×360 上下黑边；800×600 → 640×480；480×360 → 640×480；100×300 → 160×480 左右黑边 |

范围依据见 `docs/设计与优化.md`「图片缩放」一节。超出范围数码管显示 `E 4 I _ 3 2`。读卡时间随文件大小线性增加。

## 下载与启动

1. 开发板 HDMI_B 接便携屏，便携屏单独供电并选择 HDMI 输入；TF 卡插入开发板；下载线连接 TD。先调小便携屏音量。
2. TD 工具栏 `Download` → `SRAM Mode` → 文件选 `build/Emergency_Display_Baseline.bit` → `Run`。进度 100% 只表示下载完成；临时下载断电即丢失。
3. 加载期间屏幕中央显示“系统启动中 正在读取TF卡内容”，数码管最左位为 `b`，第三位显示正在读的图号 1–6；读完最左位变 `0`，出现第一张图。读卡 SPI 时钟 12.5 MHz，预计几秒内完成（以实测为准）。加载出错（如上电时卡还没准备好、偶发读错）会等 1 秒后从卡初始化自动重试，最多 3 次，仍失败才显示故障；启动看门狗 90 秒（覆盖所有重试）。若最左位为 `E`，按下方诊断码表读 6 位数码管。

## 按键

开发板丝印（手册第 19 页）：KEY1 = A2（`rst_n` 复位），K2 = B2（`key1`），K3 = B1（`key3`），K4 = C1（`key2`）。拨码开关 SW1 = C8（`alarm_sw`，手册第 18 页，拨上为 1），作为模拟的消防报警输入，20 ms 消抖；它只是板上开关，并未连接真实消防系统。

| 状态 | 操作 | 结果 |
|---|---|---|
| 任何时候 | K1 | 复位，重新读 TF 卡 |
| 任何时候 | K4 | 打开 / 关闭设置菜单（关闭即保存设置） |
| 菜单关闭 | K2 短按 | 切到下一张轮播图 |
| 菜单关闭 | K2 长按约 0.8 秒 | 普通 ↔ 注意 切换 |
| 任何时候 | 拨码开关 SW1 拨上 | 模拟消防报警：立即进入紧急模式（最高优先级，按键不能退出） |
| 任何时候 | SW1 拨下 | 退出紧急，回到按键选择的普通或注意模式 |
| 菜单关闭 | K3 | 切换调试信息开/关（调试画面 ↔ 产品画面） |
| 菜单打开 | K3 | 选下一项（到底回到第一项） |
| 菜单打开 | K2 | 当前项换到下一个值（到头回绕） |
| 菜单打开 | 10 秒不操作 | 自动关闭菜单并保存 |
| 任何时候 | K2、K4 同时按住约 2 秒 | 恢复全部默认设置，回到普通模式 |

菜单里没有长按功能；菜单外 K2 长按不会再触发短按，短按以松开为准。按键是板上演示输入，并非已连接真实消防设备。

| 模式 | 画面 | 声音 |
|---|---|---|
| 普通 | PIC1–PIC4 轮播（约 5 秒一张，或 K2 手动），按菜单所选转场 | 钟琴琶音 |
| 注意 | 商店照常营业：轮播继续，每张广告之后插入一次 PIC5 告示（进入时先显示告示）；橙色“提示”字幕和客流提示文字；屏幕四周常亮橙色细框 | 每 10 秒一次“叮—咚” |
| 紧急 | 立即切到 PIC6 疏散图（最高优先级），红色“紧急”字幕，四周红色粗框闪烁；解除后回到原来的轮播图 | 扫频警报 |

## 设置菜单

类似显示器 OSD：左上方面板，标题栏“画面与声音设置”，选中项高亮，底部提示 `K3 选择  K2 调整  K4 关闭` 和“关闭菜单即保存设置”。所有参数在下一帧消隐期生效。

| 菜单项 | 取值 | 说明 |
|---|---|---|
| 亮度 | 0–4（默认 2） | 偏移 $-32,-16,0,+16,+32$ |
| 对比度 | 0–4（默认 2） | 围绕灰度中心增益 $0.5,0.75,1,1.25,1.5$，饱和截断 |
| 音量 | 0–4（默认 2） | 0 静音，每级 6 dB |
| 转场效果 | 淡入淡出 / 滑动揭示 / 直接切换 / 交叉混合 | 轮播图与告示之间使用；交叉混合是旧图逐渐溶解成新图（约 0.55 秒，不经过黑场）；紧急事件总是直接切入 |
| 界面透明度 | 不透明 / 半透明（默认） / 高透明 | 字幕条和菜单面板透出下层图片的比例：$0$、$1/4$、$1/2$，文字带 1 像素阴影 |
| 自动轮播 | 开启 / 关闭 | 约 5 秒一张；菜单打开时暂停 |
| 节能模式 | 关闭 / 开启 屏幕调暗 | 面向夜间或无人时段：画面亮度降到 3/4，字幕滚动减为 1/4 速度，波形少刷新；不影响声音和紧急切换 |
| 调试信息 | 开启 / 关闭 | 默认开启；关闭后为面向观众的产品画面（菜单外也可直接按 K3） |

## 设置断电保存

菜单里的亮度、对比度、音量、转场、界面透明度、自动轮播、节能、调试信息八项会自动保存到板载 W25Q64 用户 Flash（手册第 17 页，P8/M9/P7/N8/P9/R9），下次上电自动恢复。不需要额外操作：

- 按 K4 关闭菜单后约 10 ms 开始写入，只需一次页编程（约 1 ms），所以关菜单后马上断电也已保存。菜单一直开着时，最后一次调整后 3 秒自动保存。K3 切换调试信息、K2+K4 恢复默认同样会被保存。
- 只用芯片最后两个 4 KB 扇区（`7FE000`、`7FF000`）轮流写，带序号和 CRC。下一次要写的扇区在上一次保存后就已在后台擦好；被擦的那个扇区从不保存最新记录，所以擦除或写入时断电，下次上电都用最新的一份完整记录。
- 上电先核对芯片 ID 为 W25Q64（`EF4017`）且无写保护，否则不写，只在本次运行内保存参数。FPGA 位流所在的配置 Flash（W25Q16，专用 MSPI 管脚）与此逻辑无连接。
- 调试状态行 `F:x`：`D` 无保存记录（默认值）、`S` 已加载/已保存、`W` 正在写入、`X` 芯片未识别或有写保护、`E` 写入失败。

验收：改亮度和音量，按 K4 关菜单后立即断电再上电，参数应保持；状态行显示 `F:S`。

## 画面层次

- **产品画面（调试信息关闭）**：全屏图片 + 底部半透明字幕条。字幕条左侧标签为“公告 / 提示 / 紧急 / 故障”，颜色分别为黄、橙、红、暗红；紧急模式下屏幕四周红框以约 2 Hz 闪烁。
- **调试信息（开启）**：额外显示顶部状态行和下方波形面板。
  - 状态行：`NORMAL/NOTICE/ALARM` 模式、`IMG` 图号 1–6、`AU` 自动轮播、`B`/`C`/`V` 档位、`FX` 转场、`ECO`、`RD`/`LD`（读出校验）、`RF`（SDRAM 控制器每秒刷新次数，十六进制）、`CC`（TF 读取 CRC 不符扇区数）、`F:`（设置保存状态），最后是开机运行时间 `时:分:秒`（板上没有实时时钟芯片，这是复位后的计时，不是日历时间）。
  - 音频面板顶行是读数：`WAVEFORM PEAK xx%`（最近约 21 ms 的峰值占满幅的百分比）和 `SPECTRUM PEAK xxxxHz yy%`（最高频段的频率和高度）；底行是坐标。
  - 左半是波形：纵轴 `+1 / 0 / -1` 为正负满幅，虚线为半幅；横轴 `0`–`5.3ms`（节能模式下为 `10.7ms`）。从上升过零点触发采集，周期音调画面静止。
  - 右半是频谱：128 点 FFT，64 根蓝色频段柱，横轴 `0 500 1k 1.5k 2k 2.5k Hz`，竖线每 500 Hz 一条，横线为 25%、50%、75%；柱顶满格表示满幅正弦。普通模式的钟琴音读数在 520–1050 Hz 之间跳动；警报时在 600–1200 Hz 之间来回变化；注意模式“叮—咚”分别约 656 Hz 和 516 Hz。频段宽 46.9 Hz，所以读数是最近的频段中心，不是精确音高。
  - 最右侧 `LV` 竖条为峰值电平。
  - 右上角红块：显示欠载或素材故障。

## 声音

FPGA 内合成 48 kHz 正弦音色，左右声道相同：

| 模式 | 声音 |
|---|---|
| 普通 | 柔和的钟琴琶音，每 0.25 秒一个音，自然衰减 |
| 注意 | “叮—咚”两声提示，每 10 秒一次（商店照常营业，不宜太频繁） |
| 紧急 | 600–1200 Hz 往返扫频警报，每秒一个来回 |

## 数码管诊断码

6 位从左到右记为 `X K I R C C` / `X K I R D D`，均为十六进制，空白表示不适用。

| 状态 | 显示 | 含义 |
|---|---|---|
| 加载中 | `b K I R C C` | `K=1` SD 卡初始化，`K=2` 读文件；`I` 为正在加载的图片 1–4；`R` 见下；`CC` 为数据 CRC 不符扇区数 |
| 正常 | `0 _ _ R C C` | 六张图全部预载；`R`、`CC` 为 0 时不显示 |
| 故障 | `E K I R D D` | 见下表 |

| `K` | 阶段 | `DD` 含义 |
|---|---|---|
| `1` | SD 卡初始化 | `01/02` CMD0 无响应/响应错；`03/04/05` CMD8；`06/07` CMD55；`08/09` ACMD41 超时/响应错；`0A/0B/0C` CMD58 或 OCR 未就绪 |
| `2` | FAT32 卷与根目录扫描 | `10` 扇区读失败（看 `R`）；`20` 无 55AA 签名；`21` 不是 FAT32（含 exFAT、GPT）；`22` 六个固定文件名不全 |
| `3` | 第 `I` 张文件簇链 | `10` 扇区读失败；`23` 簇链成环；`24` 簇号越界；`25` 文件提前结束；`26` 簇数超限 |
| `4` | 第 `I` 张（1–6）BMP 格式 | `31` 非 BM；`32` 宽或高超出 16–2048；`33` planes；`34` 非 24 位；`35` 压缩；`36` 像素偏移；`37` 长度/像素数不符；`38` 上游读错 |
| `5` | 第 `I` 张写 SDRAM | `42` 写缓存溢出；`44` 解码错误；`45` 写入数不足；`46` SDRAM 写超时或跨时钟握手无应答 |
| `6` | 未报错但图未齐 | `DD` 低位为已完成图片位图 |
| `F` | 90 秒启动看门狗 | `DD` 高位为加载器状态（1 初始化、2 读文件），低位 1 表示卡已初始化 |

`R` 为本次启动第一个底层扇区读错误：`0` 无；`1` R1 超时；`2` R1 状态错；`3` 数据令牌超时；`4` 错误令牌；`5` 数据 CRC 错（仅开启 CRC 检查的构建）；`6` 卡未就绪；`E` 字节顺序错。单个扇区最多重试 3 次。当前构建与官方例程一致，数据 CRC 只计数不判错（SPI 非保护模式）。

## SDRAM 刷新修复与读出校验

2026-11-01 实板：静止彩色错点随时间增多，越久未显示的图越多，复位重新加载后消失；状态行 `RF:0000`，说明控制器在一秒内没有发出任何刷新。原因在官方 `global_def.v`：

$$\texttt{SELF\_REFRESH\_INTERVAL}=64000000/\texttt{SDR\_CLK\_PERIOD}/2^{11},\quad \texttt{SDR\_CLK\_PERIOD}=1000000000/125000000$$

宏没有括号，按整数从左到右展开为 $64000000/1000000000/125000000/2048=0$，控制器内部的刷新计数器停在 0，自刷新请求永不产生。官方例程每次按键都重新从 TF 卡写图，所以不易暴露；本项目的图片长期驻留，就会逐渐丢数据。

修复在 `rtl/ed_framebuffer.v` 的 `ed_sdram` 模块：与官方 `sdram.v` 结构相同，加密控制器和 SDRAM 原语不改，只把原来接 0 的 `App_ref_req` 改由项目调度器驱动。调度器每 15.6 µs 先拉高 `ref_hold`，读写两路在当前 128 字突发结束后不再开始新突发；总线空闲 16 拍后才发刷新请求，等控制器刷新窗口结束再释放。

2026-11-01 第一版直接每 15.6 µs 打一个刷新脉冲：静止错点消失，但出现每帧位置都在变的白色短横。仿真复现了原因：刷新插进读突发中间，刷新后不到 tRFC 就发出的行激活会被 SDRAM 忽略，这几次读回的是悬空总线（全 1，即白色）。`sim/tb_sdram_refresh.sv` 用官方加密控制器加行为级 SDRAM 模型（`sim/sdram_model.sv`）对比三种情况：官方配置刷新 0 次；直接打脉冲有 11 次 tRFC 违例，204800 个字中 44 个错误；调度后 207 次刷新，0 违例，0 错误。原先每帧补读的临时方案已删除（状态行不再有 `SC`）。

| 状态行 | 期望 |
|---|---|
| `RF` | 约 `F000`–`FA00`（每秒约 6 万次刷新）；`0000` 表示刷新仍未工作 |
| `RD` | `00`：同一张图前后帧读出一致 |
| `LD` | `00`：读出与开机写入一致 |
| 数码管 `CC` | TF 读取时数据 CRC 不符的扇区数；当前卡每个扇区都不符，可能是该卡在 SPI 非保护模式下不发有效 CRC，图像正确时可忽略 |
## 按顺序验收

| 检查 | 操作 | 应看到／听到 |
|---|---|---|
| 基础图片 | 启动后观察 PIC1 | 正向、颜色正常、无半帧、无右上角红块 |
| 错点复查 | 切到注意、紧急再回普通，等 10 分钟后逐张查看 | 无静止彩色错点；`LD` 保持 `00` |
| 手动与自动 | 菜单关自动轮播，反复短按 K2；再打开 | 四张轮播图依次切换；开关自动轮播不回第一张 |
| 缩放 | 查看 PIC2（800×600 缩小）与 PIC4（480×360 放大） | 都铺满全屏、比例正确，文字可读 |
| 模式 | 长按 K2 进入注意；再把 SW1 拨上 | 注意：先显示告示，之后广告与告示交替轮播，橙色标签和橙框，叮咚声；紧急：立即切到疏散图、红框闪烁、警报音 |
| 恢复 | 紧急时长按 K2 无效；把 SW1 拨下 | 回到进入紧急前的注意或普通模式，轮播继续 |
| 报警开机 | SW1 拨上时上电 | 读完 TF 卡后直接进入紧急模式 |
| 菜单 | K4 打开，K3 选项、K2 调整、K4 关闭 | 选中高亮移动；亮度/对比度/音量条变化；界面透明度三档可见差别；下一帧生效 |
| 产品画面 | 按 K3 或在菜单里关闭调试信息 | 顶部状态行和波形消失，只剩图片和字幕条 |
| 异常素材 | 断电后移除 PIC6 或换无卡再启动 | 屏幕中央显示读取异常，数码管 `E…`；修复后按 K1 |
| 稳定性 | 连续轮播至少 30 分钟，切换模式及参数 | 无红块、卡死、图错位、错点 |

## 固化与断电自启

先完成上述临时下载验证和时序分析，再用 TD 下载器的板载配置 Flash 编程流程烧写同一位流。位流写入配置 Flash W25Q16（原理图 `3_Power_and_Config.pdf` 的 U39，手册第 22 页，专用 MSPI 管脚 R11/P10/T3/T10，JEDEC ID `EF4015`）；菜单设置在另一片用户 Flash W25Q64（`EF4017`），两片电路独立，烧写位流不影响已保存的设置。改了代码就要重新烧写。2026-11-02 已首次固化。固化后断开下载线、完全断电，再单独给开发板与便携屏供电，重复启动至少 10 次，每次应自行加载 TF 内容并出图出声。
